Настройка Callback API ВКонтакте для ответа на «Старт» / «start»
================================================================

1. Управление сообществом → Настройки → Работа с API → Callback API.
2. URL сервера: https://altdi.ru/api/vk/callback  (или ваш домен + путь)
3. Версия API: 5.199 (или актуальная, как в VK_API_VERSION).
4. Событие: входящее сообщение (message_new).

Переменные окружения на сервере (.env):

  VK_BOT_TOKEN=...              (токен сообщества с правом messages)
  VK_CALLBACK_CONFIRMATION=...  (строка подтверждения из настроек Callback в ВК, например fe17a41e)
  VK_CALLBACK_SECRET=...        (тот же «Секретный ключ», что в поле ВК — если задан, без него message_new не примем)

После сохранения ВК отправит POST type=confirmation — ответ должен быть ТОЛЬКО этой строкой (text/plain), без HTML и без JSON.

Если ВК пишет «Сервер вернул неправильный ответ» или «Invalid response code»:
  Чаще всего POST вообще не доходит до server.cjs: домен обслуживает Next.js, а /api/vk/callback даёт 404/HTML → не HTTP 200 и не строка fe17a41e.

  Что сделать (любой один способ):
  A) Nginx: см. doc/nginx-vk-callback-snippet.conf — отдельный location = /api/vk/callback на 127.0.0.1:ПОРТ_server.cjs
  B) Next.js: см. doc/nextjs-proxy-vk-callback-route.ts — прокси на тот же server.cjs (MEDIA_SERVER_URL), плюс pm2 держит server.cjs на этом порту.

  Общее:
  1) В .env процесса, который реально отвечает на /api/vk/callback: VK_CALLBACK_CONFIRMATION=fe17a41e (как в ВК), затем pm2 restart ... --update-env
  2) Проверка: curl -sS -w "\nHTTP:%{http_code}\n" -X POST https://altdi.ru/api/vk/callback -H "Content-Type: application/json" -d "{\"type\":\"confirmation\",\"group_id\":238093187}"
     Должно быть: тело ровно fe17a41e и HTTP 200. Если HTML или 404 — маршрутизация не та.

Пользователь: кнопка на сайте ведёт на https://vk.com/altdiru , первое сообщение — Старт/старт/Start/start.
